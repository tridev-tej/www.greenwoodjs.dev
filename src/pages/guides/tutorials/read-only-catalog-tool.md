# Build and test a read-only catalog tool with Greenwood

By [Tejesh Vaish](https://tejeshvaish.com), Lead Engineer at Lumian.ai and an IIT Kanpur CSE graduate. Works on AI agents and backend systems.

Build an endpoint that accepts `{"sku":"notebook"}` and returns one product. Greenwood owns the route and catalog lookup. A native-fetch client supplies the SKU.

Bad input tests the boundary between the framework and your route. In Greenwood `0.34.0`, malformed JSON is rejected before your route runs. That response is plain text. The route's validation errors are JSON. Build the lookup, then test both parts of the contract through the real server.

This example uses synthetic public data. It needs no model, SDK, database, account, or API key. An agent adapter could call the endpoint later, but no agent or MCP integration is implemented here.

## Add one API route

Create <code style="overflow-wrap: anywhere;">src/pages/api/tools/catalog.js</code>. Greenwood maps that file to `/api/tools/catalog`. Its exported async `handler` takes a standard `Request` and returns a standard `Response`, as described in the [API routes documentation](https://greenwoodjs.dev/docs/pages/api-routes/).

### <code style="overflow-wrap: anywhere;">src/pages/api/tools/catalog.js</code>

<!-- prettier-ignore-start -->

<app-ctc-block variant="snippet" heading="src/pages/api/tools/catalog.js">

<!-- prettier-ignore -->
<div style="width: 100%; overflow-x: auto; padding-top: 32px;" tabindex="0">
<div style="width: max-content; min-width: 100%; padding-right: 1em; box-sizing: border-box;">

  ```js
  import { findProduct } from "../../../data/catalog.js";
  
  function json(body, status, extraHeaders = {}) {
    return new Response(JSON.stringify(body), {
      status,
      headers: {
        "Content-Type": "application/json; charset=utf-8",
        "Cache-Control": "no-store",
        ...extraHeaders,
      },
    });
  }
  
  function validInput(input) {
    return input !== null
      && typeof input === "object"
      && !Array.isArray(input)
      && Object.keys(input).length === 1
      && typeof input.sku === "string"
      && /^[a-z0-9-]{1,32}$/.test(input.sku);
  }
  
  export async function handler(request) {
    if (request.method !== "POST") {
      return json({ error: "method_not_allowed" }, 405, { Allow: "POST" });
    }
    const mediaType = (request.headers.get("content-type") ?? "").split(";")[0].trim().toLowerCase();
    if (mediaType !== "application/json") return json({ error: "unsupported_media_type" }, 415);
    const input = await request.json();
    if (!validInput(input)) return json({ error: "invalid_input" }, 400);
    const product = findProduct(input.sku);
    if (!product) return json({ error: "product_not_found" }, 404);
    return json({ product }, 200);
  }
  ```

</div>
</div>

</app-ctc-block>

<!-- prettier-ignore-end -->

For requests that reach it, the handler first checks the method and media type. It accepts `application/json`, including a parameter such as `charset=utf-8`. It then validates the parsed value: exactly one property, `sku`, containing 1 to 32 lowercase letters, digits, or hyphens. Arrays, missing fields, numeric SKUs, extra fields, and long SKUs are rejected before lookup. There's no default SKU or case conversion.

Known keys return one complete catalog record. Unknown keys return a JSON `404`. Route-owned responses declare JSON and `Cache-Control: no-store`; unsupported methods also declare `Allow: POST`.

The `request.json()` call isn't the first JSON parser in this server. Greenwood's pinned [development and hybrid-server implementation](https://github.com/ProjectEvergreen/greenwood/blob/v0.34.0/packages/cli/src/lifecycles/serve.js) installs `koaBody()` before route handling. Its [Request conversion](https://github.com/ProjectEvergreen/greenwood/blob/v0.34.0/packages/cli/src/lib/resource-utils.js) serializes the parsed JSON value again when constructing the handler's Request.

A catch around this route's `request.json()` cannot change a response already returned by an upstream parser. Counting bytes in the handler's reconstructed body doesn't measure the original wire body either. The SKU length check is an application constraint; an ingress body-size limit belongs at the server or hosting boundary.

```text
Request -> Greenwood framework parser
  Malformed JSON, null, or whitespace-only JSON body
    -> 400 text/plain; charset=utf-8: Bad Request; no catalog lookup
  Parsed input -> route
    Method check -> 405 JSON if unsupported
    Media-type check -> 415 JSON if unsupported
    Shape validation -> 400 JSON if invalid
    Catalog lookup -> 200 JSON if found; 404 JSON if missing
```

  ```js
  const [base, sku] = process.argv.slice(2);
  if (!base || !sku) throw new Error("Usage: node client.mjs <base-url> <sku>");
  
  async function readResponse(response) {
    if (![200, 400, 404, 405, 415].includes(response.status)) {
      throw new Error(`Undocumented HTTP status: ${response.status}`);
    }
    const type = response.headers.get("content-type");
    const raw = await response.text();
    if (type === "application/json; charset=utf-8") {
      JSON.parse(raw);
      return raw;
    }
    if (response.status === 400 && type === "text/plain; charset=utf-8") {
      if (raw !== "Bad Request") throw new Error("Unexpected framework error body");
      return raw;
    }
    throw new Error(`Undocumented response content type: ${type}`);
  }
  
  let response;
  try {
    response = await fetch(new URL("/api/tools/catalog", base), {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ sku }),
      signal: AbortSignal.timeout(5000),
    });
  } catch (error) {
    console.error(`TRANSPORT ${error.name}: ${error.message}`);
    process.exit(2);
  }
  
  console.log(`HTTP ${response.status}`);
  try {
    const body = await readResponse(response);
    console.log(body);
  } catch (error) {
    console.error(`RESPONSE ${error.name}: ${error.message}`);
    process.exit(3);
  }
  if (!response.ok) process.exitCode = 1;
  ```

The client checks the status and content type before interpreting the body. It parses each JSON body to validate it. The known framework `400` response is accepted only with its exact plain-text type and `Bad Request` body. An unknown status, type, or framework body fails the response check. There is no try-JSON-then-text parsing path.

Fetch normally resolves when an HTTP error response arrives, so the client checks `response.ok`.

A transport failure instead prints `TRANSPORT` and exits 2. An unreadable or undocumented response prints `RESPONSE` and exits 3. [Fetch response handling](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch)

If no server can be reached, `TRANSPORT TypeError: fetch failed` describes a connection failure. Receiving an HTTP `404` means the server replied and the product wasn't found.

  ```js
  import assert from "node:assert/strict";
  import { createHash } from "node:crypto";
  import { readFile } from "node:fs/promises";
  
  const [base] = process.argv.slice(2);
  if (!base) throw new Error("Usage: node check.mjs <base-url>");
  const catalogUrl = new URL("./src/data/catalog.js", import.meta.url);
  const before = createHash("sha256").update(await readFile(catalogUrl)).digest("hex");
  const product = {
    sku: "notebook",
    name: "Plain notebook",
    priceCents: 450,
    currency: "USD",
  };
  const cases = [
    ["known", "POST", '{"sku":"notebook"}', 200, { product }],
    [
      "malformed", "POST", '{"sku":', 400, "Bad Request",
      "application/json", "text/plain; charset=utf-8",
    ],
    [
      "null", "POST", "null", 400, "Bad Request",
      "application/json", "text/plain; charset=utf-8",
    ],
    ["array", "POST", "[]", 400, { error: "invalid_input" }],
    ["missing", "POST", "{}", 400, { error: "invalid_input" }],
    ["numeric", "POST", '{"sku":42}', 400, { error: "invalid_input" }],
    [
      "extra", "POST", '{"sku":"notebook","tool":"delete"}',
      400, { error: "invalid_input" },
    ],
    [
      "long-sku", "POST", JSON.stringify({ sku: "a".repeat(33) }),
      400, { error: "invalid_input" },
    ],
    ["unknown", "POST", '{"sku":"missing"}', 404, { error: "product_not_found" }],
    [
      "prototype-name", "POST", '{"sku":"constructor"}',
      404, { error: "product_not_found" },
    ],
    ["method", "PUT", '{"sku":"notebook"}', 405, { error: "method_not_allowed" }],
    [
      "media-type", "POST", '{"sku":"notebook"}',
      415, { error: "unsupported_media_type" }, "text/plain",
    ],
    [
      "whitespace", "POST", " ".repeat(257), 400, "Bad Request",
      "application/json", "text/plain; charset=utf-8",
    ],
    ["padded-known", "POST", '{"sku":"notebook"}'.padEnd(256), 200, { product }],

  function checkResponse(response, raw, status, expected, responseType, name) {
    assert.equal(response.status, status, name);
    assert.equal(response.headers.get("content-type"), responseType, name);
    const cache = responseType === "application/json; charset=utf-8" ? "no-store" : null;
    assert.equal(response.headers.get("cache-control"), cache, name);
    assert.equal(response.headers.get("allow"), status === 405 ? "POST" : null, name);
    if (responseType === "text/plain; charset=utf-8") {
      assert.equal(raw, expected, name);
      return;
    }
    assert.deepEqual(JSON.parse(raw), expected, name);
  }

    method,
    body,
    status,
    expected,
    mediaType = "application/json",

      method,
      headers: { "Content-Type": mediaType },
      body,
      signal: AbortSignal.timeout(5000),

    const raw = await response.text();
    console.log(`CASE ${name}\nHTTP ${response.status}`);
    console.log(JSON.stringify(Object.fromEntries(response.headers), null, 2));
    console.log(raw);
    checkResponse(response, raw, status, expected, responseType, name);
  }
  const after = createHash("sha256").update(await readFile(catalogUrl)).digest("hex");
  assert.equal(after, before, "catalog source bytes changed");
  console.log(`14 cases passed; catalog SHA-256 unchanged: ${after}`);
  ```

## Keep the boundary small

This tool reads public synthetic data. A request cannot choose a module, operation, file, or outbound URL. A future agent adapter needs its own implementation and tests, including how it exposes framework errors to its caller.

Shape validation doesn't identify a caller or grant permission to read private products. If you replace this catalog with private data, authenticate the caller and enforce access at the data read. Keep the framework parser, route validation, and catalog lookup as separate observable steps in the HTTP test.
